# Signed apk feed on GitHub Pages, built by GitHub Actions

## Rationale

The fullcone packages were installed from local files (`apk add --allow-untrusted`), so every
update meant a local build plus `install.sh`, and `apk upgrade` could not see new versions. A
signed feed lets routers install and upgrade through apk like any official package. More
packages will follow, so the repository was renamed from `openwrt-fullcone` to
`openwrt-packages` and restructured so a new package or release needs no build-script change.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Hosting | Public repository `0ekk/openwrt-packages`, GitHub Pages deployed from Actions (`upload-pages-artifact` + `deploy-pages`) | Free; a Pages site is public even for a private repository, and the content was already redacted. The site is rebuilt from scratch on every run, so there is no `gh-pages` branch state |
| Layout | (replaced on 2026-11-18, see "Official-style layout") `<release>/<target>/packages.adb` plus the `.apk` files; `keys/openwrt-packages.pem` at the root | kmods are tied to one target kernel, so the target (not just the arch) is part of the path |
| Signing | Only the index is signed (`apk mkndx --sign`, EC P-256), as the SDK does (`package/Makefile:136`); packages stay unsigned, the index pins their hashes | Same trust model as the official feeds; routers trust the feed through one public key in `/etc/apk/keys/` |
| Key handling | Private key only in the Actions secret `APK_SIGN_KEY`; written to `$RUNNER_TEMP` in a separate step after the SDK build and deleted after signing; the index is verified against `keys/` before upload | The build runs third-party code (SDK, upstream sources) that never sees the key; a wrong secret fails the run instead of publishing an index routers reject. No local copy: a lost key is replaced by rotating (README) |
| Prebuilt packages | `prebuilt.list` holds `<sha256> <url>` lines for noarch upstream release files; `build.sh` downloads each, checks the hash and copies it to `out/`, so it is in every release's index | OpenClash's release `.apk` also contains dashboards, GeoSite/GeoIP and China IP data that its release workflow downloads at build time and the git source lacks; a source build would ship a different package. Publishing the release file keeps exactly what was installed by hand before, with its hash pinned twice (list and index) |
| Package discovery | `package/` is a feed (`src-link local`); `feeds install -a -p local` pulls build dependencies from the base feed; the package list comes from `feeds list -r local`; each `package/<dir>` is compiled | Adding a package is adding a directory; no hard-coded package or dependency names in `build.sh` |
| Releases | One `sdk/<release>-<target>.env` per SDK (name, sha256, kernel pin), written by `sdk/new.sh <release> <target>` from the release's `sha256sums` and `kmods/<version>-<release>-<vermagic>/` directory; `build.sh` reads the base feed commit from the SDK's `feeds.conf.default`; the workflow matrix is `ls sdk/*.env` | A firmware upgrade is a new file, made before any router runs the release (the first version needed a router to read the pin from); keeping the old file keeps the old feed online until routers move |
| Kernel pin | Taken from the env file instead of reading a router over SSH; `build.sh` fails if the SDK's vermagic or a kmod's `kernel=` dependency differs | CI has no router; apk on the router stays the final guard |
| owut index | The sign step also writes `index.json` next to `packages.adb`, with the SDK's own command (`apk adbdump --format json` piped to `scripts/make-index-json.py -f apk -a <arch>`) | owut (attended sysupgrade) reads `<feed>/index.json` for every custom feed, with the release in the URL replaced by the target release, and stops on a 404 |
| Tests | `test/lab.sh` is generic (`up`, `down`, `check` installs `out/*.apk` and sources every `test/<package>/check.sh`); fullcone assertions moved to `test/fullcone/check.sh`, the NAT checker to `test/fullcone/check_nat.py` | Per-package tests live next to each other without touching the lab |
| Download host | `MIRROR` (default `https://downloads.openwrt.org`) for the SDK and the lab image and feeds; `install.sh` defaults to `ROUTER=root@192.168.1.1` | CI runs outside China; local runs can use a nearby mirror; no real LAN address in the repository |
| Triggers | Push to `main` touching `package/`, `sdk/`, `build.sh`, `prebuilt.list` or `keys/`, plus manual dispatch | Docs-only pushes must not republish the same versions with different hashes |
| Supply chain | Actions pinned by commit SHA (checkout v7.0.1, upload-artifact v7.0.2, download-artifact v8.0.2, upload-pages-artifact v5.0.0, deploy-pages v5.0.1, all released at least two weeks earlier); workflow permissions `contents: read`, `pages: write` and `id-token: write` only in the deploy job | Least privilege; a moved tag cannot change what runs |
| License | GPL-2.0 for the whole repository (`LICENSE`), replacing the Apache-2.0 file the GitHub repository was created with | `package/fullconenat` derives from GPL-2.0 code (ImmortalWrt Makefile, patches to the kernel module), which cannot be relicensed and is incompatible with Apache-2.0; one license keeps the feed simple |
| Router trust | Public key in `/etc/apk/keys/openwrt-packages.pem`, listed in `/etc/sysupgrade.conf`; feed line in `/etc/apk/repositories.d/customfeeds.list` | `sysupgrade -l` keeps `customfeeds.list` and the official key, but not an unowned key file |

## Impact

- Anyone can download the packages; only the holder of `APK_SIGN_KEY` can publish an index a
  router accepts. Whoever controls the GitHub account or the secret can install code as root on
  routers that trust the key.
- Every package change needs a `PKG_RELEASE` or version bump, or `apk upgrade` keeps the old one.
- The feed key also vouches for the files in `prebuilt.list`: their content is only as trustworthy
  as the upstream build, but a changed upstream file fails the hash check instead of being published.
- After switching, `apk upgrade` updates the fullcone packages from the feed; packages installed
  from files were pinned to their file hash in `/etc/apk/world` until re-added by name.
- Attended sysupgrade cannot include feed packages: `sysupgrade.openwrt.org` rejects custom
  feeds; procedure in [docs/firmware-upgrade.md](../firmware-upgrade.md).
- `apk add -u <packages>` also upgrades their dependencies when the official feeds have newer
  ones (here `luci-base`); `apk upgrade --available` replaces every package whose exact build
  is not in a feed. To touch only feed packages, simulate first and pin a version if needed.

## Browsable index pages (2026-11-18)

### Rationale

The user wants the Pages site to be browsable like https://fantastic-packages.github.io/releases/
(the Jekyll theme "ghpages-mini-fileserver": an "Index of /path" page per directory). Before this
change, `/` returned 404 and the other directories 404'd too. The exception was
`<release>/<target>/`, where Pages served `index.json` as the directory index.

### Decisions

| Topic | Decision | Why |
|---|---|---|
| Generator | `.github/pages-index.py SITE BASE_URL COMMIT`, stdlib Python, run in the deploy job after `keys/` is copied. It writes a static `index.html` into every directory: breadcrumb heading, Name / Size table (directories first), footer with the build time and commit | The site is uploaded as an artifact, so Jekyll never runs. Static pages need no JS, no external assets and no new action or permission |
| Root page | Intro, link to the README, the signing key commands once, then one block per feed found in the tree (`echo <feed>/packages.adb >> /etc/apk/repositories.d/customfeeds.list`, `apk update`) | Same commands as the README, but generated from what was actually published, so a new `sdk/*.env` shows up by itself |
| Feed pages | A directory holding `packages.adb` shows its own repository line above the listing | The line to copy is on the page the user is looking at |
| No Date column | Footer "Built <UTC> from <commit>" instead | Every run rebuilds and uploads all files, so per-file dates would all equal the deploy time |
| Link check | After writing, every relative `href` must resolve inside `SITE`, and every directory must have its page; otherwise exit 1, and the deploy stops before upload | A generator bug cannot publish a broken site |
| Bare feed URL | `<release>/<target>/` now returns the HTML page instead of `index.json` | owut fetches `index.json` by name (`replace(repo, "packages.adb", "index.json")`, efahl/owut 55ed17f `files/owut` line 901), and apk fetches `packages.adb` and the `.apk` files by name |
| Trigger | Unchanged (package inputs only). After editing the generator, run the workflow by hand, as for workflow edits | A rebuild republishes the same versions with new hashes |

### Impact

- `https://0ekk.github.io/openwrt-packages/` shows the install commands and the tree; every
  directory is browsable.
- Package files, `packages.adb`, `index.json` and the key are unchanged.

## Official-style layout (2026-11-18)

### Rationale

The user wanted the feed path to name the architecture (`x86_64`) instead of the target
(`x86/64`). The feed ships `kmod-ipt-fullconenat`, which only installs on one target's exact
kernel, and several targets can share an architecture. So the user chose (AskUserQuestion) the
official download server's split: `packages/<arch>/` for kernel-independent packages and
`targets/<target>/` for kernel modules. Routers already on the old path keep a working copy for
now.

### Decisions

| Topic | Decision | Why |
|---|---|---|
| Layout | `<release>/packages/<arch>/`: every package except `kmod-*`. `<release>/targets/<target>/`: the `kmod-*` packages. Each has its own signed `packages.adb` and `index.json`, and a router adds both lines | Same split as downloads.openwrt.org; owut fetches `index.json` per repository line, so each feed needs one |
| Old path | `<release>/<target>/` is still published with every package. Its page says "Deprecated" and shows the exact switch commands (`sed` the old line to the packages feed, `echo` the targets line, `apk update`). The root page mentions it | Pages cannot redirect apk requests, and existing routers would break on the next `apk update`. It is removed once the user confirms the router has switched |
| Shared script | `.github/feed-site.sh SDK_ENV SITE` (key in `APK_SIGN_KEY`, public keys in `KEYS_DIR`, default `keys/`) holds the old sign step: lay out, sign, verify, write `index.json`. CI calls it; the local test runs the same script with a throwaway key | One implementation, so a local test exercises what CI runs. The key file exists only while `apk mkndx` signs; the SDK's verify and `make-index-json.py` run after it is deleted, as before |
| Overwrite guard | The deploy downloads the artifacts unmerged and fails if a `<release>/packages/<arch>` directory comes from two builds, then copies them into `site/` | Two targets of one release with the same arch would otherwise overwrite each other's files and leave an index that does not match its packages |
| Index pages | `pages-index.py` sorts feeds into packages, targets and legacy. The root shows one block per target with both lines (arch from the targets feed's `index.json`). Packages and targets pages say a router needs both | The commands come from what was published |

### Impact

- New installs need two repository lines; the README and the root page show them.
- Routers on the old line keep working until the copy is removed. One line of either new feed
  alone gives a clear apk error (`kmod-ipt-fullconenat (no such package)` with only the packages
  feed).
- While the old copy exists, Pages holds each package twice: about 26 MB per release, most of it
  OpenClash.
- `docs/firmware-upgrade.md`'s release `sed` still works, since the release is a path segment.

### Verification

  packages): three feeds per release, all `OK` on verify. The targets feed holds only the kmod,
  the packages feed the other four, the old path all five. No key file was left in `/tmp`.
- Overwrite guard on a fake `parts/` tree: two releases pass; a second `25.12.5/packages/x86_64`
  fails with the message.
- `pages-index.py` on that tree: 18 pages, link check passed. Screenshots of the root (two lines
  per target, the old-path note), the old feed page (Deprecated and switch commands) and a targets

- QEMU lab against the local feed (served to the VM at `10.0.2.2`, throwaway public key installed):

  - The switch commands extracted from the old feed's page leave exactly the two new lines;
    `apk update` reads both, and `apk upgrade --simulate` lists none of the feed's packages and

  - After removing the packages, a fresh `apk add luci-app-fullcone` with the two lines installs
