# Signed apk feed on GitHub Pages, built by GitHub Actions

## Rationale

The fullcone packages were installed from local files (`apk add --allow-untrusted`), so every
update meant a local build plus `install.sh`, and `apk upgrade` could not see new versions. A
signed feed lets routers install and upgrade through apk like any official package. More
packages will follow, so the repository was renamed from `openwrt-fullcone` to
`openwrt-packages` and restructured so a new package or release needs no build-script change.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Hosting | Public repository `0ekk/openwrt-packages`, GitHub Pages deployed from Actions (`upload-pages-artifact` + `deploy-pages`) | Free; a Pages site is public even for a private repository, and the content was already redacted. The site is rebuilt from scratch on every run, so there is no `gh-pages` branch state |
| Layout | `<release>/<target>/packages.adb` plus the `.apk` files; `keys/openwrt-packages.pem` at the root | kmods are tied to one target kernel, so the target (not just the arch) is part of the path |
| Signing | Only the index is signed (`apk mkndx --sign`, EC P-256), as the SDK does (`package/Makefile:136`); packages stay unsigned, the index pins their hashes | Same trust model as the official feeds; routers trust the feed through one public key in `/etc/apk/keys/` |
| Key handling | Private key only in the Actions secret `APK_SIGN_KEY`; written to `$RUNNER_TEMP` in a separate step after the SDK build and deleted after signing; the index is verified against `keys/` before upload | The build runs third-party code (SDK, upstream sources) that never sees the key; a wrong secret fails the run instead of publishing an index routers reject. No local copy: a lost key is replaced by rotating (README) |
| Package discovery | `package/` is a feed (`src-link local`); `feeds install -a -p local` pulls build dependencies from the base feed; the package list comes from `feeds list -r local`; each `package/<dir>` is compiled | Adding a package is adding a directory; no hard-coded package or dependency names in `build.sh` |
| Releases | One `sdk/<release>-<target>.env` per SDK (name, sha256, base feed commit, kernel pin); the workflow matrix is `ls sdk/*.env` | A firmware upgrade is a new file; keeping the old file keeps the old feed online until routers move |
| Kernel pin | Taken from the env file instead of reading a router over SSH; `build.sh` fails if the SDK's vermagic or a kmod's `kernel=` dependency differs | CI has no router; apk on the router stays the final guard |
| Tests | `test/lab.sh` is generic (`up`, `down`, `check` installs `out/*.apk` and sources every `test/<package>/check.sh`); fullcone assertions moved to `test/fullcone/check.sh`, the NAT checker to `test/fullcone/check_nat.py` | Per-package tests live next to each other without touching the lab |
| Download host | `MIRROR` (default `https://downloads.openwrt.org`) for the SDK and the lab image and feeds; `install.sh` defaults to `ROUTER=root@192.168.1.1` | CI runs outside China; local runs can use a nearby mirror; no real LAN address in the repository |
| Triggers | Push to `main` touching `package/`, `sdk/`, `build.sh` or `keys/`, plus manual dispatch | Docs-only pushes must not republish the same versions with different hashes |
| Supply chain | Actions pinned by commit SHA (checkout v7.0.1, upload-artifact v7.0.2, download-artifact v8.0.2, upload-pages-artifact v5.0.0, deploy-pages v5.0.1, all released at least two weeks earlier); workflow permissions `contents: read`, `pages: write` and `id-token: write` only in the deploy job | Least privilege; a moved tag cannot change what runs |
| License | GPL-2.0 for the whole repository (`LICENSE`), replacing the Apache-2.0 file the GitHub repository was created with | `package/fullconenat` derives from GPL-2.0 code (ImmortalWrt Makefile, patches to the kernel module), which cannot be relicensed and is incompatible with Apache-2.0; one license keeps the feed simple |
| Router trust | Public key in `/etc/apk/keys/openwrt-packages.pem`, listed in `/etc/sysupgrade.conf`; feed line in `/etc/apk/repositories.d/customfeeds.list` | `sysupgrade -l` keeps `customfeeds.list` and the official key, but not an unowned key file |

## Impact

- Anyone can download the packages; only the holder of `APK_SIGN_KEY` can publish an index a
  router accepts. Whoever controls the GitHub account or the secret can install code as root on
  routers that trust the key.
- Every package change needs a `PKG_RELEASE` or version bump, or `apk upgrade` keeps the old one.
- After switching, `apk upgrade` updates the fullcone packages from the feed; packages installed
  from files were pinned to their file hash in `/etc/apk/world` until re-added by name.
- Attended sysupgrade still cannot include feed packages: remove them first, as before.
- `apk add -u <packages>` also upgrades their dependencies when the official feeds have newer
  ones (here `luci-base`); `apk upgrade --available` replaces every package whose exact build
  is not in a feed. To touch only feed packages, simulate first and pin a version if needed.

## Verification (2026-11-01)

- Local clean build with the new `build.sh` (about 11 min): `feeds list -r local` found the
  four packages; same versions and dependencies as before, kmod pinned to the env file's kernel.
- `test/lab.sh check`: `test/fullcone/check.sh` passed all five assertions.
- Signing: an index signed with the key verified `OK` against `keys/`, `UNTRUSTED` (exit 1)
  against an empty key directory.
- First workflow run: `Index has 4 packages`, `out/packages.adb: OK`, deployed. From outside:
  the Pages key equals `keys/openwrt-packages.pem`, the downloaded index verifies, packages
  return HTTP 200.
- QEMU: packages installed from files, then key + feed added: `apk update` accepted the
  index, `apk add <names>` turned the hash-pinned world entries into names, `sysupgrade -l`
  lists the key and `customfeeds.list`. Same-version local builds are not replaced
  (`apk fix --reinstall`: "APK unavailable"), so the releases were bumped (r3, r3, r2); after
  the next run `apk add -u` upgraded the four packages from Pages, still full cone, dmesg clean.
- Router: same switch, then `apk add -u` for the three backend packages and
  `apk add luci-app-fullcone=2` followed by `apk add luci-app-fullcone` (leaves `luci-base`
  alone). Installed r3/r3/r3/2, world entries are plain names, `mode fullcone`, LAN host
  reports Full Cone (NAT1), dmesg clean, nlbwmon running, tailscale UDP true. The changed
  default `/etc/config/fullcone` arrived as `.apk-new` (live config kept) and was removed.
- Router reboot (requested by the user): WAN back after about 70 s; `xt_FULLCONENAT` loaded at
  boot from the r3 package, `mode fullcone` from the firewall include without manual steps,
  dmesg clean, nlbwmon and tailscale UDP fine, the feed index still trusted, LAN host reports
  Full Cone (NAT1).
